# IDEA — 研究点子管理系统

> 系统性地生成、评估和管理研究想法，而非依赖随机的灵感。

## 目录结构

```
IDEA/
├── 01-灵感收集/          # 点子收集与头脑风暴
│   ├── 索引.md            # 中央登记册 — 所有点子 + 文献新颖性地图
│   ├── 想点子指南.md       # 七种发散方法论
│   ├── 待评估点子.md       # 点子收集池（非结构化）
│   └── evidence-log.md    # 新颖性检索证据日志
├── 02-评估中/            # 正在评估的点子
│   └── [点子名]/
│       └── 评估白皮书.md
├── 03-进行中/            # 正在进行的项目
├── 04-已归档/            # 已完成或放弃的项目
├── 05-文献库/            # 文献笔记 — 每篇论文一个文件
└── README.md             # 本文件
```

## 数据流

```
文献库/ (文献笔记)
        ↓ 初始化/同步时扫描分类
索引.md (新颖性基线 + 缺口 + 点子登记)
        ↓ 指导
想点子指南.md (7种发散方法)
        ↓ 应用方法
待评估点子.md (点子池) ──→ 索引.md (登记，状态: 待评估)
        ↓ 调研评估
02-评估中/[点子名]/ (评估白皮书)
        ↓ 更新状态
索引.md (待评估 → 评估中 → 进行中 → 已归档)
```

## 文件职责一览

| 文件 | 职责 | 一句话规则 |
|------|------|-----------|
| `01-灵感收集/索引.md` | 索引 + 新颖性地图 + 生命周期跟踪 | 中央登记册 — 所有点子 + 文献一览 |
| `01-灵感收集/想点子指南.md` | 方法论 | 如何想点子 — 学到新方法就更新 |
| `01-灵感收集/待评估点子.md` | 点子池 | 头脑风暴原始输出，一行一个 |
| `01-灵感收集/evidence-log.md` | 证据日志 | 每个新颖性声明必须链接到检索证据 |
| `02-评估中/[点子名]/评估白皮书.md` | 评估文档 | 每个评估中的点子一个文件夹 |
| `05-文献库/*.md` | 文献笔记 | 一篇论文一个文件，构建新颖性基线 |
| `scripts/validate_idea_index.py` | 一致性校验 | 检查索引、点子池、文件夹三者一致 |

## 核心理念

1. **文献先行，点子在后** — 先了解已有什么，再考虑新点子
2. **新颖性需要证据** — 没有检索证据就不能声称"这是新的"
3. **索引是唯一真理来源** — 所有点子从诞生一刻就登记在索引中
4. **一个评估 = 一个文件夹** — 每个评估中的点子有自己的文件夹和白皮书
5. **诚实评分** — 3.0 分意味着"合格"，不是"好"

## 快速开始

```bash
# 1. 创建目录结构
mkdir -p IDEA/{01-灵感收集,02-评估中,03-进行中,04-已归档,05-文献库}

# 2. 复制模板文件（此处替换为实际 source 路径）
cp /path/to/assets/*.md IDEA/01-灵感收集/
cp /path/to/assets/README.md IDEA/

# 3. 开始填充文献库
# 在 05-文献库/ 中为每篇相关论文创建笔记

# 4. 初始化索引
# 阅读所有文献笔记 → 填入索引.md 的新颖性地图

# 5. 开始想点子！
# 阅读 01-灵感收集/想点子指南.md 获取方法论
```
